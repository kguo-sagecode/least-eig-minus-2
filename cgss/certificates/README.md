# SageMath checks for C1–C24

The scripts in this directory check, in SageMath 10.9, the computations C1 to C24 of the
formalization of [CGSS], with the LDLᵀ data of Remark 3.11, and write their certificates to
`data/` (25 JSON files, whose format `data/README.md` describes). The generators
use exact Sage arithmetic and independently constructed root systems, graphs and designs; they do
not import or execute the project's other Python checks. The certificates are exact data, outside
the trust base: several of the Lean computations in `LineGraphs/Computations/` take their data
from them (transcribed, or generated by the scripts in `LineGraphs/scripts/`) and check it in the
kernel. A run of these scripts is an independent check, not a proof.

## Running

From the top of the repository (the runner works from any directory), run

```bash
cgss/certificates/run_all.sh
```

It runs every `c*.sage`, then `remark311_ldl.sage` and `verify_certificates.sage`, each as
`sage file.sage` (some SageMath launchers do not accept `-python`), with the SageMath executable
that the variable `SAGE_BIN` names (see the script for its default), as in
`SAGE_BIN=$(command -v sage) cgss/certificates/run_all.sh`. It keeps Sage's state, temporary
files and caches in `.sage`, `.tmp` and `.cache` in this directory, stops on the first failure,
and writes the output of each script, with its running time, to the file `<script>.log` next to
it. The full run takes about half a minute; each script takes seconds.

To run one script, run it from this directory with the same environment:

```bash
mkdir -p .sage .tmp .cache data
export DOT_SAGE="$PWD/.sage" TMPDIR="$PWD/.tmp" XDG_CACHE_HOME="$PWD/.cache"
export PYTHONDONTWRITEBYTECODE=1
sage c13_c15_cospectral.sage
```

The last script, [verify_certificates.sage](verify_certificates.sage), reloads the emitted files,
rejects floats, checks their witnesses and cross-file indices, and writes
`data/manifest.json`: the SHA-256 hashes of the 25 certificates and of the source files of
the run, and the SageMath version. The manifest is an output of the run and is not kept in the
repository.

The other files are [common.py](common.py), the exact helpers that the scripts share (the JSON
encoding of exact values, the root systems, graphs and designs, and the certificate writer), and
[c23_lean_data.py](c23_lean_data.py), plain Python with networkx, which prints the Lean tables of
`LineGraphs/Computations/C23.lean` for Example 5.13: the 1-factorization of K₆ (k = 2), the
isomorphisms of its graph H with the pair graph of the (6,3,10,5,2) design and with the line graph
of `SimpleGraph.petersen`, the hyperoval design 2-(28,4,1) with its resolution (k = 4), and the
residual of the (37,9,2) biplane of quartic residues modulo 37. Run it with
`python -I c23_lean_data.py`.

## What the checks do not establish

The checks for arbitrary classical ranks are explicitly bounded instances. The symbolic identities
in C1, C8, C10–C12 and C14 apply to indeterminates with the mathematical denominators assumed
nonzero. C17's positive eigenvectors give the maximality of the eigenvalue only together with the
monotonicity lemma SM1 of `cgss/prerequisites.md`. C18 proves a finite list of necessary
parameters; it does not claim that every arithmetic-feasible parameter set is realized by a graph.
C22 uses nauty's unlabelled regular-graph enumeration, and needs the reduction SE4 of
`cgss/prerequisites.md` to those 11 representatives. The Lean library proves these two steps
itself (SM1 in `LineGraphs/Spectral/StrictMono.lean`, SE4 in `LineGraphs/Seidel/`).
